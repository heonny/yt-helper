# yt-helper

YouTube Music 재생목록 두 개를 나란히 띄워 놓고 곡을 드래그로 복사하거나 옮기는 로컬 웹 도구입니다. YouTube Music 웹에서 수백 곡짜리 재생목록을 정리하기 느리고 불편해서 만들었습니다.

> **내 컴퓨터에서만 실행하세요.** yt-helper는 내 YouTube 로그인 쿠키를 들고 동작합니다. 기본 설정에서는 `127.0.0.1`로만 열리고 다른 주소로 들어온 요청을 Host 검사가 거부합니다. 이 바인딩이나 Host 검사를 고치거나, ngrok 같은 터널에서 Host 헤더를 바꿔 외부에 열면, 접속한 사람 누구나 내 계정으로 재생목록을 바꾸고 지울 수 있습니다. 서버나 여러 사람이 접속하는 컴퓨터에도 올리지 마세요. 다른 사람이 쓰게 하려면 그 사람이 자기 컴퓨터에서 직접 실행하고 자기 쿠키로 연결해야 합니다.

## 할 수 있는 일

- 재생목록 두 개를 좌우 또는 위아래로 띄우고, 고른 곡을 반대쪽으로 드래그해 복사합니다. 이동 모드를 켜면 원본에서 뺍니다.
- 넣을 재생목록에 이미 있는 곡은 건너뜁니다. 반대쪽에 이미 있는 곡에는 목록에서 "반대쪽에 있음" 표시가 붙습니다.
- 곡명, 아티스트, 앨범으로 검색하고 제목이나 아티스트 순서로 정렬합니다. 정렬은 화면 순서만 바꾸고 실제 재생목록 순서는 그대로 둡니다.
- 클릭으로 한 곡, Shift+클릭으로 범위를 고르고 delete 키로 고른 곡을 지웁니다.
- 새 재생목록을 만들고, 내가 만든 재생목록을 지웁니다. 남의 재생목록을 보관함에 저장한 경우에는 복사만 할 수 있습니다.
- 빠르게 연달아 한 작업은 큐에 쌓여 순서대로 처리되고, 위쪽 진행 막대에 몇 번째 작업인지 나옵니다.

## 준비물

- Python 3.9 이상
- YouTube Music에 로그인된 Chrome
- macOS와 Windows에서 같은 방법으로 인증합니다.

## 설치

```bash
git clone <저장소 주소> yt-helper
cd yt-helper
python3 -m pip install --user -r requirements.txt
```

## 실행과 인증

```bash
python3 app.py
```

브라우저가 `http://127.0.0.1:8765/#token=...` 주소로 열립니다. 이 토큰은 실행할 때마다 새로 만들어지고, 화면이 API를 부를 때 함께 보내야 서버가 요청을 받습니다. 브라우저가 열리지 않거나 탭을 닫았다면 터미널에 출력된 주소를 그대로 여세요. 서버를 다시 시작한 뒤 예전 탭에 "접속 토큰이 맞지 않습니다"가 뜨면, 새로 열린 탭을 쓰거나 터미널의 새 주소를 여세요. 서버를 끄려면 터미널에서 `Ctrl+C`를 누르세요. macOS 기본 Python이 띄우는 `NotOpenSSLWarning`이 거슬리면 `python3 -W ignore app.py`로 실행하세요.

처음 실행하면 "YouTube Music 연결" 창이 뜹니다. yt-helper는 브라우저의 로그인 쿠키로 YouTube Music에 요청을 보내므로, 그 쿠키를 한 번 붙여넣어야 합니다.

1. Chrome에서 https://music.youtube.com 에 로그인합니다.
2. 개발자도구를 엽니다. Mac은 `Cmd+Opt+I`, Windows는 `F12`입니다. **Network** 탭 필터에 `youtubei/v1/browse`를 입력합니다.
3. YouTube Music 화면에서 "보관함"을 클릭합니다. 목록에 POST 요청이 나타납니다.
4. 그 요청을 우클릭하고 **Copy → Copy as cURL**을 고릅니다. Windows에서는 cmd와 bash 중 어느 쪽을 골라도 됩니다.
5. 연결 창의 입력칸에 붙여넣고 **연결**을 누릅니다. Request Headers 원문을 붙여넣어도 됩니다.

붙여넣은 내용은 이 컴퓨터에서 실행 중인 yt-helper로만 전달되고, yt-helper는 이 쿠키로 YouTube Music에만 요청합니다. 다른 서버로는 보내지 않습니다. yt-helper는 계정 정보를 한 번 읽어 로그인이 살아 있는지 확인한 뒤에만 저장합니다. 쿠키는 내 사용자 폴더의 `~/.config/yt-helper/browser.json`에 저장됩니다. macOS와 Linux에서는 파일 권한 600, 폴더 권한 700으로 내 계정만 읽을 수 있습니다. Windows에서는 사용자 폴더의 기본 접근 권한에 맡깁니다. 프로젝트 폴더 밖에 두므로 git이나 폴더 공유로 함께 나가지 않습니다. 파일로 저장하므로 브라우저나 서버를 꺼도 연결이 유지됩니다.

왼쪽 위의 연결 상태 버튼이 지금 상태를 보여줍니다. 초록 점과 함께 "계정이름 연결됨", 빨간 점과 함께 "연결 안 됨"이나 "인증 만료"로 나옵니다. 이 버튼을 누르면 연결 창이 열려 언제든 다시 붙여넣을 수 있습니다. 로그인이 풀려 YouTube가 HTTP 401을 돌려주면 상태가 "인증 만료"로 바뀌고 연결 창이 뜹니다. 처리 중이던 큐 작업은 다시 연결될 때까지 기다렸다가 이어서 처리됩니다.

연결을 끊으려면 연결 상태 버튼을 누르고 연결 창의 **인증 해제**를 누르세요. 저장된 쿠키 파일을 지웁니다. 이 쿠키가 Google 쪽에서도 쓸 수 없게 하려면 YouTube에서 로그아웃하세요.

이전 버전처럼 프로젝트 폴더에 `browser.json`이 있으면, 다음 실행 때 `~/.config/yt-helper/`로 옮기고 원래 파일은 지웁니다.

## 쓰는 방법

- 각 화면 위쪽의 드롭다운에서 재생목록을 고릅니다. 드롭다운은 내 재생목록, 저장한 남의 재생목록, 좋아요나 Recap 같은 자동 목록으로 나뉩니다.
- 곡을 고르고 반대쪽 목록으로 끌어다 놓거나 "반대쪽으로 보내기"를 누릅니다.
- 10곡 이상을 옮기거나 지울 때와 재생목록을 지울 때만 확인 창이 뜹니다. 지운 곡을 되돌리는 기능은 없습니다.
- 오른쪽 위의 "재생목록 갱신" 버튼은 보던 재생목록, 검색어, 정렬, 스크롤 위치를 그대로 둔 채 최신 내용을 다시 받습니다. `Cmd+R`로 페이지를 새로 고쳐도 같은 위치로 돌아옵니다.
- 큐에 처리 전인 작업이 남아 있으면 페이지를 닫거나 새로 고칠 때 브라우저가 경고합니다. 큐는 페이지 메모리에만 있어서 새로 고치면 보내지 못한 작업이 사라집니다.

## 주의할 점

- **`~/.config/yt-helper/browser.json`을 공유하거나 올리지 마세요.** 이 파일만 있으면 누구나 이 계정으로 YouTube Music을 쓸 수 있습니다. 실수로 올렸다면 파일을 지우는 것으로는 부족하고, YouTube에서 로그아웃해 쿠키를 무효로 만들어야 합니다.
- yt-helper는 공식 API가 아닌 [ytmusicapi](https://github.com/sigma67/ytmusicapi)를 씁니다. YouTube가 응답 형식을 바꾸면 기능이 깨질 수 있습니다. 실제로 재생목록 삭제 응답 형식이 바뀌어 `app.py`의 `delete`에서 따로 처리하고 있습니다.
- 서버는 `127.0.0.1`에서만 열리고, 다른 Host 헤더, JSON이 아닌 POST 요청, 접속 토큰이 없는 API 요청을 거부합니다. 그래서 같은 네트워크의 다른 기기, 다른 웹사이트, 토큰을 모르는 같은 컴퓨터의 다른 계정이나 프로그램은 이 서버를 쓸 수 없습니다.
- 시작할 때 인증 파일과 폴더의 소유자와 권한을 점검합니다. 내 소유가 아니면 쓰지 않고, 권한이 600과 700보다 열려 있으면 경고를 출력하고 고칩니다.
- 곡 정보는 한국어로 받습니다. 바꾸려면 `app.py`의 `main`에서 `language`와 `location` 값을 고치세요.

## 파일 구성

| 파일 | 역할 |
|---|---|
| `app.py` | 로컬 HTTP 서버. 화면 요청을 ytmusicapi 호출로 바꾸고, 붙여넣은 cURL에서 인증 헤더를 뽑아 저장합니다. |
| `index.html` | 화면 전체. 별도 빌드 없이 서버가 그대로 보냅니다. |
